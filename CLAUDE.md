# Behavioral Guidelines

## 1. Think Before Coding
- Never assume undocumented behavior.
- Ask questions when requirements are ambiguous.
- Explain important assumptions before implementing.

## 2. Simplicity First
- Prefer the simplest working solution.
- Do not create abstractions unless they are clearly needed.
- Do not add features that were not requested.

## 3. Surgical Changes
- Modify only the minimum amount of code necessary.
- Do not refactor unrelated code.
- Preserve existing comments and style unless asked.

## 4. Goal-Driven Execution
- Define clear success criteria before coding.
- Verify the implementation with tests or validation.
- Stop once the requested goal is achieved.

## 5. Analyze Before Implementing

Before writing any code, analyze the requested feature as a whole.

- Identify affected user flows.
- Consider normal, edge, and failure cases.
- Look for possible regressions.
- Evaluate impacts on related modules and data.
- Explain important risks or missing requirements before coding.

Keep the implementation minimal. Do not add code for hypothetical scenarios unless explicitly requested.
